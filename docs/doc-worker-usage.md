# Document Worker 使用指南（三层收敛版）

> 状态：正式接入 Codex（2026-08-16）| 模型：qwen3:4b（本地 Ollama）

## 1. 定位

本地文档工人负责"把已经定义清楚的事情大量做掉"；DeepSeek 主脑负责"决定应该怎么做"和最终审核。

```
Codex + DeepSeek 主脑
   │ MCP 调用（传文件路径，不传正文）
   ▼
Document Worker（qwen3:4b）
   文件读取 → 分块 → 本地推理 → 合并 → Schema 校验 → 返回浓缩结果
```

## 2. 工具面（MCP，共 4 个）

| 工具 | 参数 | 层 |
|---|---|---|
| `extract_requirements` | `source_path` | L1 全本地 |
| `generate_test_cases` | `source_path`, `requirement_id?`, `output_format?`, `extra_instructions?` | L1 全本地（首个正式生产能力） |
| `decompose_requirements` | `source_path`, `output_format?`, `extra_instructions?` | L2 本地生成 + DeepSeek 审核 |
| `get_status` | 无 | 诊断 |

`output_format` 支持 `json` / `markdown` / `table`，由主代理按场景自选。

## 3. 三层使用模式

### L1 全本地（不消耗 DeepSeek token）

**测试用例生成**已通过两轮验证，直接产出：

> "对 `docs/xxx.md` 生成测试用例，覆盖正常/边界/异常，输出 markdown 表格"

`requirement_id` 可定向生成（例如只针对 `REQ-003`），实测 4B 会按相关功能域收敛，但不会严格到只留一条——主代理可再过滤。

**需求提取**同样可信：正确区分功能/非功能/验收标准/待确认，无编造。

### L2 本地生成 + DeepSeek 审核（需求分解）

分解初稿由本地出，**主代理只做审核，不要重新生成整份结果**。推荐审核协议：

> "以上是本地生成的 {n} 条需求分解，请审核，只返回：
> `{"issues": ["每条问题一句话"], "required_repairs": ["需要重做的条目 id 或明确修改"]}`"

已知错误模式（审核重点）：
- **臆造**：如 BMS 分解中编造"30 分钟完成全流程"约束；
- **过度分解**：把环境配置/约定也拆成"需求"；
- **软约束写死**：文档里"尽量 3 秒内"被写成硬性 ≤3s。

### L3 直接交给 DeepSeek（Worker 不接）

以下任务已实测超出 4B 能力边界，**不要调用本地 Worker**：

- HTML+SVG 笔记编写/重写（规划泄漏、长文截断，两轮实验均失败）；
- 复杂技术创作、跨模块推理、架构设计；
- 需要严格绘图纪律的 SVG 生成。

## 4. 使用规则

1. **传文件路径，不传正文**：主代理只传 `source_path`，Worker 自己读文件；否则 token 已经烧在主上下文里，本地化失去意义。
2. **结果必审**：L1 任务主代理快速扫一眼，L2 任务按第 3 节协议审核。
3. **超时预期**：单文档单任务 12~77s（8K 上下文纯 GPU）；长文档按 3000 字符分块，多块任务线性变慢。
4. **偶发空结果**：Worker 已内置"主条目为空自动重试一次"；若仍失败会报错，主代理重试或改全云端。

## 5. 后续优化（暂不做，等使用反馈）

- **任务化分块**：需求分解按 `##/###` 切，测试用例按需求 ID/功能模块切，而不是固定字符数——文档规模上来后再做；
- 若出现"某类文档创作强烈希望本地完成"的明确反馈，再拉 qwen3:8b 定向对照。
